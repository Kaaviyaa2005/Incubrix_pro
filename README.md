# Incubrix Pro — Script and Voiceover to B-roll Video Engine

A local-first FastAPI + FFmpeg prototype for turning a script or recorded voiceover into a captioned B-roll video. It includes a responsive editing UI, local clip selection, live microphone recording, automatic speech transcription, and downloadable video metadata.

## Windows setup

1. Extract the project.
2. Put only media you have rights to use in `data/stock_clips/<Category>/` (Business, City, Finance, Nature, Technology).
3. Install Python 3.10+ and FFmpeg/FFprobe.
4. In PowerShell at the project root:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python -m uvicorn app.main:app --reload
```

5. Open `http://127.0.0.1:8000`.

Microphone recording requires a browser permission prompt. The live recording is captured as WebM in supported browsers. Audio transcription uses `faster-whisper`; its model is downloaded on first use and needs sufficient disk/RAM. Set `ASR_MODEL` (default `small`), `ASR_DEVICE` (default `cpu`), and `ASR_COMPUTE_TYPE` (default `int8`) in the environment.

## User workflow

- Enter a script to generate TTS narration, or upload/record narration without entering a transcript.
- Audio-only inputs are transcribed automatically. The transcript is shown in the script field after generation.
- Select B-roll scene-by-scene, adjust caption font, colour, and effects, then open Preview. Preview generation renders a video with audio and selected caption styling; it can take a few minutes.
- Download MP4, SRT, timeline JSON and manifest JSON.

## API currently implemented

- `GET /health`, `GET /ready`
- `GET /api/v1/health`, `GET /api/v1/library`
- `GET/POST /api/v1/projects`, `DELETE /api/v1/projects/{pid}`
- `POST /api/v1/generate` (synchronous render)
- `GET /media/{clip_path}`, `GET /outputs/{job}/{filename}`

## Important assessment gaps — do not claim these as complete

The supplied assessment PDF requires more than a working UI. This version is still a prototype and does **not yet satisfy all must-haves or the Integration Standard**:

- B-roll selection is based on filenames/categories and keyword overlap, not semantic/vision-language understanding. Relevance scores are heuristic.
- The local media index says `Needs verification`; licensing, attribution and commercial rights must be verified clip-by-clip. Watermarked preview clips are excluded by filename, but that is not a full rights-screening system.
- Repeats can occur when there are too few eligible clips; the selector discourages but does not guarantee zero repeats.
- Audio is transcribed with Whisper when the optional ASR dependency/model is available. Silent/music-only inputs return a clear error, but language/accuracy needs evaluation.
- Preview renders the current complete video, rather than a low-resolution proxy; this is accurate but not instant.
- Only one aspect ratio is rendered per request. Scene timing is weighted by word count rather than forced alignment to actual spoken word timestamps.
- Jobs are synchronous, not durable background jobs. There is no Idempotency-Key support, callback/HMAC support, S3/MinIO storage, correlation-ID logging, rate limiting, or authentication.
- Docker Compose, a complete OpenAPI 3.1 contract, provider adapters/fallback, a batch runner, end-to-end test pack, independent vision-language relevance scoring, clip-only partial rerender, Hindi/Tamil quality evaluation, and measured throughput/cost figures still need implementation and evidence.
- The code does not generate new footage; all clips come from the local dataset. Never claim AI-generated footage.
- Do not expose this development server publicly without authentication, upload limits, rate limiting, and deployment hardening.

## Audio input modes

The editor has three mutually exclusive input modes:

1. **Script** — enter text; the service creates narration with the selected Edge TTS voice.
2. **Audio file** — upload MP3, WAV, M4A, AAC, OGG or WebM. The app transcribes it with faster-whisper before scene matching.
3. **Live recording** — record in a supported browser; the recorded WebM is transcribed by the same ASR pipeline.

For uploaded/recorded audio, choose **Keep my original voice** to retain the source recording, or **Use selected text-to-speech voice** to re-speak the automatic transcript using the selected TTS voice. The transcript is generated by the app; users are not asked to type it.

Automatic transcription requires `faster-whisper` and its model download on first use. A clear speech recording is required; silent/music-only input returns an explicit transcription error. Browser microphone access requires permission and a secure context (localhost is allowed).

Captions are generated as `captions.srt`; when **Burn captions in** is enabled, FFmpeg/libass renders the selected caption style into the MP4. The rendered preview uses the resulting MP4 with its AAC audio track. If a video plays silently, verify the browser player is not muted and confirm the file has both video and audio streams with `ffprobe`.

## Metadata-driven media library

- The metadata catalog lives at `data/media_library.json`; it is seeded with the 15 dataset filenames in the five expected categories.
- In the **Media library** page, use **Add a video** to upload MP4, MOV, MKV, or WEBM and enter descriptive and rights metadata. The video is saved under `data/stock_clips/<Category>/`; metadata is appended to `data/media_library.json`.
- Technical fields (duration, resolution, frame rate, video/audio codec, and file size) are read with FFprobe. Install FFmpeg/FFprobe for technical extraction and preview support.
- Retrieval ranks title, description, tags, keywords, visual elements, mood, and category. The renderer avoids using the same clip in adjacent scenes when an alternative is available, including when adjacent scene overrides request the same clip.
- This is metadata-based retrieval, not visual scene understanding. Write descriptions/tags that accurately describe the actual footage; review low-confidence matches and verify licensing before commercial use.
- Supported upload size is currently 500 MB per video.
